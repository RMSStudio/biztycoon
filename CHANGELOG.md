## strategy-DLC v0.2 — Monte-Carlo, события фасилитатора, отчёт (2026-06-11)

Продолжение B2B-режима, по-прежнему без правок ядра:

- **🎲 Monte-Carlo**: N прогонов (по умолч. 60) от текущего состояния до горизонта сессии; «автопилот без новых решений» ведёт контракты и добирает проекты, но не нанимает. Синхронный цикл с подменой `EventBus.emit` — без мерцания UI, реальное состояние восстанавливается. Сводка по решению §7.3: 4 ключевых показателя крупно (вероятность банкротства с вердиктом, медианный финал с квартилями, % кассовых разрывов, месяц пикового напряжения) + гистограмма распределения + детализация
- **⚡ События фасилитатора**: библиотека из 6 шоков (урезание бюджета, уход клиента, хантинг сотрудника, задержка оплаты, просадка рынка, горячий лид) + конструктор «месяц × тип × параметр». Срабатывают через обёртку `advanceMonth` — действуют и внутри Monte-Carlo (стресс-тест стратегии с заложенными шоками)
- **📄 Отчёт-артефакт**: markdown-файл одной кнопкой — вводные сессии, метрики текущей линии, все ветки с исходами, сводка Monte-Carlo, заложенные события, журнал решений
- Попутный фикс ядра (отдельный коммит): копирайтеры в пуле кандидатов + ролевой volume — V-капы проектов снова выполнимы
- Смоук-тест расширен до 23 проверок — зелёные

## strategy-DLC v0.1 — B2B-режим «Стратегическая сессия» (2026-06-11)

**Подключаемый модуль `dlc/strategy/` — ядро игры не модифицировано** (одна data-запись в реестре лоадера). Выключен DLC — игра прежняя. Первые 3 шага по `design_b2b_edition.md`:

- **Сидируемый RNG**: при старте сессии `Math.random` подменяется mulberry32-генератором; состояние в `G._rngState` → сериализуется сейвами, ветка продолжает тот же поток случайности. Одинаковый seed = одинаковая «погода» для всех участников
- **Импорт цифрового двойника** (JSON, шаблон `twin_example.json` на примере IT-аутсорс студии): баланс, overhead, штат поимённо (роль/грейд/зарплата/лояльность), действующие контракты с остатками бюджета и прогрессом — стартуют сразу в work-фазе без попапов. Win-условие отключается: сессия завершается отчётом
- **Ветки гипотез**: «⑂ Развилка» (снапшот через _snap/_restore из saves.js), «📌 Зафиксировать исход», возврат на развилку с авто-фиксацией линии; **сравнение веток** — таблица метрик (финал/реп/штат/ФОТ/сдачи) + помесячный кэшфлоу линий рядом
- UI: карточка режима на экране выбора специализации (seed, горизонт, файл двойника), панель сессии в игре, модалка сравнения — всё DOM-инжектом из модуля
- Мягкий горизонт: по достижении N месяцев — сводка ключевых показателей, игра не обрывается
- Смоук-тест `sim/test-strategy.js`: 16 проверок (двойник, детерминизм, ветки) — зелёные

## v3.0 — Единый фазовый пул: все проекты через lifecycle, тиры T1–T7 (2026-06-11)

### Один пул — один флоу
- **Все проекты «Скаутинга» идут через lifecycle-флоу** — `signProject` всегда запускает `initLCState`. Кнопка «🧪 LC-тест» и `doLifecycleScouting` удалены; бывшие тестовые проекты (Лендинг для кафе, Ребрендинг «ТехноСтарт», Онлайн-магазин «Каприз») влиты в общий пул
- **Профили цепочек** (`projects.js CHAIN_PROFILES`): instant (1 work-фаза, без ревью — разовые) / short (T1) / standard (T2–T3, 2 work) / full (T4–T5, 3 work + юридика) / epic (T6–T7, **5 work-фаз**); `phaseProfile` переопределяется в дефиниции, юридика — при requiresLegal или юристе в штате. Движок и UI генерализованы под 1–5 work-фаз

### Предоплата — переговорная механика
- Поле **`prepayChance`** у проекта (или тир-дефолт 25→65%): в шаге «Условия оплаты» появляется «Попробовать выбить аванс 30% (шанс ~X%)»; юрист +15%. Успех — аванс в кассу (−5 настроения), отказ — −3 настроения, +3 риска. У части проектов предоплаты нет вовсе — карточка скаутинга честно показывает шанс или «без предоплаты»
- Старая автопредоплата при подписании удалена; попутно закрыт баг: аванс не вычитался из бюджета (двойная выплата)

### Тиры T1–T7
- Бюджеты: T2 2–4M (фазовая себестоимость), T3 5–9M, **T5 18–35M, T6 35–70M, T7 75–150M**; нагрузки 4/8/14/18/24/32/40; длительности 4/7/10/12/14/17/20; milestone T5–T7 — 25%×3
- Гейты: T5 rep≥85+портф.30, T6 rep≥90+портф.50, T7 rep≥95+портф.80; редкость **legendary** (rep≥90); 7 новых проектов: Федеральный банк, Ритейл-сеть «Полка», Авиакомпания «Высота» (T5), «Недра», Экосистема «Сфера» (T6), Цифровизация региона, Глобальный бренд «Atlas» (T7)

### Разовые проекты
- Работают через назначение команды, как все: instant-цепочка, `_duration` 1 — при мощности ≥ нагрузки готовы за месяц; бронирование (`_scheduled`/`toggleOneTimeSchedule`) удалено; оплата через finishDelivery

### Сопутствующие фиксы и баланс
- **finishDelivery не начислял портфолио** — LC-сдачи не двигали гейты тиров; исправлено (+тир×3)
- **Дедлайн с буфером ×1.6+2 мес**: `_duration` описывает идеальный темп, реальный фазовый цикл длиннее — штраф наказывает плохое ведение, а не сам флоу (закрывает хроническую утечку репутации)
- Валидация sim2-lc (бот: команда 4, Q-перки, разовые в приоритете): победы M27–M35, медиана финала ~5.2M, банкротства редки, 0 софтлоков. Winrate бота ~15–20% — фазовая партия глубже и сложнее v2.6; калибровка под живую игру — после плейтеста
- Классический симулятор `sim/sim2.js` устарел (нефазового пути больше нет), актуален `sim/sim2-lc.js`

## v2.5 — Единая система оценки клиента: mood + NPS (фикс п.26) (2026-06-11)

### Объединение двух систем (п.26)
- **`nudgeClientRating(c, delta)`** (engine.js) — единый канал изменения отношения клиента: для LC-проектов пишет в `_lcClientMood` и зеркалит в `clientNPS`; для обычных — в `clientNPS` как раньше. Все источники переведены на него: `nudgeAllNPS` (события algo/conflict/discount), удар усталости в `advanceMonth`, `investInClient`, событие «discount → Отказать» (agency.js)
- **`updateAllNPS`**: LC-клиенты исключены из старых драйверов (Q/V-гэп −14/−10, overload, manager/HR, шум) — их отношение формируется решениями фаз, work-событиями и действиями игрока; помесячно применяются только модификаторы проекта (`nps_passive`/`nps_drain`), churn-порог общий (<25)
- **`moodDelta`** (projects.js) теперь мгновенно зеркалит mood в `clientNPS` — **фикс «Промежуточного показа»**: эффект (+10 😊) был невидим, т.к. карточка проекта рендерит NPS, а тот жил отдельной жизнью
- **`initLCState`**: стартовое настроение = `npsStart` проекта (было фикс. 60) — дифференциация клиентов (lc_simple 78, lc_risky 58) работает и в LC-флоу

### Валидация (sim2-lc, 10 прогонов без --lc-shield)
Мгновенный churn исчез: lc_simple сдаётся стабильно (был 0/26 у всех LC), уходы сместились с M2–M6 на M11–M32 и стали следствием накопленного негатива (усталость → mood-удары, события, дренаж lc_risky) при нехватке денег на менеджмент настроения. Зеркало mood→NPS — 0 расхождений. Экономика LC-цикла по-прежнему отрицательная — ждёт п.27 (поэтапные выплаты)
